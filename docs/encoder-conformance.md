# Encoder Conformance Specification

This document describes the password encoder rules for Rust and TypeScript implementations.

## Profile Baseline

Profile version 1 uses the algorithm identifier upspa-password-encoding-v2. The reference commit is fd00014 from the repository history. The test suite uses the 22 vectors in vectors.json. The tested environment uses Rust 1.81.0, Node.js 24.19.0, and Python 3.12.

## Inputs

The encoder function takes four inputs:
- Secret key material as a string.
- Site password policy object or JSON string.
- Account name or email string.
- Non-negative integer counter for rotation.

## Normalization Rules

Before making a password, the policy is normalized:
- Minimum length is at least 8.
- Maximum length is at most 64.
- Maximum length is never smaller than minimum length.
- If whitespace is forbidden, spaces are removed from allowed symbols.
- Repeated symbols in allowed symbols are removed.
- If a symbol is required but the allowed symbols list is empty, it uses !@#$%^&* by default.
- Forbidden words are trimmed and converted to lowercase.
- The account name is trimmed and converted to lowercase.
- The policy is converted into a compact JSON string with a fixed key order.

## Candidate Generation

The encoder creates candidate passwords deterministically:
- A seed string combines the algorithm name, secret, canonical policy, account name, counter, and attempt number from 0 to 127.
- SHA-256 block hashing expands the seed into bytes.
- The password length is selected between minimum and maximum bounds.
- One character is picked for each required character class.
- The rest of the password is filled from the combined pool of allowed characters.
- Characters are shuffled using the generated bytes.
- If the candidate passes all policy rules, it is returned.
- If all 128 attempts fail, the encoder returns an error.

## Counter Semantics

The counter is a stable number. Changing the counter creates a new password for rotation. When using the same counter, the encoder always returns the same password. Registration and login produce identical passwords when given the same counter.

## Reproduction Commands

Run the full qualification test suite with this command:

```bash
./scripts/run_encoder_conformance.sh
```

You can also run individual steps:

```bash
cargo test --locked -p upspa-core --test vectors_password_encoder
cargo test --locked -p upspa-core --test encoder_properties
npm -w upspa-extension test -- src/shared/passwordPolicy.test.ts
./node_modules/.bin/tsx scripts/gen_password_vectors.mjs
git diff --exit-code -- test-vectors/compatibility-profile-v1/
./scripts/verify_corpus_corruption.sh
python3 tools/security-gates/run_gates.py .
```

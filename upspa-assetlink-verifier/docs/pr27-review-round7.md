## Reviewer Finding (P2): Reject Literal Control Characters in JSON Strings

### Problem
RFC 8259 section 7 states:
> "All Unicode characters may be placed within the quotation marks, except for the characters that MUST be escaped: quotation mark, reverse solidus, and the control characters (U+0000 through U+001F)."

Previously, `PureAssetLinkVerifier.verifyRawJson` delegated string parsing to Moshi's `JsonReader.nextString()`. Moshi's reader accepts unescaped control characters (`U+0000` to `U+001F`) without throwing an exception. Consequently, an `assetlinks.json` containing literal control characters (e.g. in relation entries, package names, namespaces, fingerprints, or object keys) successfully decoded and verified as `VerificationResult.Verified` rather than failing closed with `VerificationResult.Rejected.InvalidJsonFormat`. Because `UpSpaAssetLinkVerifier.verify` fetches and delegates raw JSON to `PureAssetLinkVerifier.verifyRawJson`, both verification paths were affected.

### Fix
1. Added a strict, non-throwing pre-scan `hasUnescapedControlCharInString(rawJson: String): Boolean` in the shared parsing path of `PureAssetLinkVerifier.verifyRawJson`:
   - Scans characters while tracking string boundary state (`inString`) and escape state (`escaped`).
   - If a quote (`"`) is encountered outside a string, `inString` becomes true.
   - Inside a string:
     - If the preceding character was an unescaped backslash (`escaped == true`), the escape sequence ends (`escaped = false`). If the escaped character itself is `< 0x20`, it returns `true`.
     - An unescaped backslash (`'\\'`) toggles `escaped = true`.
     - An unescaped quote (`'"'`) toggles `inString = false`.
     - Any literal character `< 0x20` (`' '`) encountered inside a string immediately returns `true`.
   - Whitespace outside of strings (space, tab, LF, CR) is ignored.
   - Non-ASCII characters (e.g. `'ğ'`) and DEL (`0x7F`) inside strings remain valid per RFC 8259.
   - Escaped characters such as `\n`, `\t`, `\r`, `\u0000`, `\u001f`, `\"`, and `\\` stay valid.
   - If a string ends with an escaped backslash (`"abc\\"`), the closing quote correctly closes the string.
   - The scanner does not throw exceptions on unterminated strings or syntax errors, leaving structural parse validation to Moshi.
2. If `hasUnescapedControlCharInString(rawJson)` returns `true`, `verifyRawJson` immediately returns:
   ```kotlin
   VerificationResult.Rejected.InvalidJsonFormat(
       "JSON contains unescaped control character (U+0000 to U+001F) in string"
   )
   ```
3. Because `UpSpaAssetLinkVerifier.verify` delegates raw JSON parsing to `PureAssetLinkVerifier.verifyRawJson`, both public entry points are protected.
